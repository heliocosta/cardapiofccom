# Research & Design Decisions: site-foundation

## Summary
- **Feature**: `site-foundation`
- **Discovery Scope**: Extension (brownfield hugoplate install, project-setup mode) with targeted external verification of Hugo behaviour. Light discovery (`design-discovery-light.md`) plus executable probes.
- **Key Findings**:
  - Hugo does **not** fall back from a regional i18n file to its base language: `pt-br` with no `pt-br.yaml` renders English, and a partial `pt-pt.yaml` falls back to English for missing keys. Per-key fallback is achieved with config-only **single-file i18n mounts** (`i18n/pt.yaml → i18n/pt-pt.yaml`) declared **before** the `i18n → i18n` directory mount; keys then merge and project regional files win.
  - `site.Language` exposes `Lang`, `Locale`, `Label`, `Direction`, `Params` but **no time zone accessor**. The language-level `timeZone` only affects parsing of offset-less dates. Templates need the zone name in the edition params; consistency with the language `timeZone` can be asserted via `(time.AsTime "2000-01-01T00:00:00").Location.String`.
  - Go zone abbreviations are unreliable for display (`America/Sao_Paulo` prints `-03`; `Europe/Lisbon` printed `UTC` in a localised format). The visible zone indicator must come from the registry label plus a computed numeric offset.
  - `time.Format` localises weekday/month names per edition locale (`domingo, 8 de novembro`), so localised layouts can live in i18n files; there is no `lang.FormatDate` function (the brief's mention is corrected to `time.Format`).
  - With `defaultContentLanguageInSubdir = false`, Hugo emits an `/en/` alias page; `disableDefaultLanguageRedirect = true` removes it.
  - `resources.Concat` errors on an empty slice; the theme's cached `essentials/script.html` and `style.html` concatenate lazy plugin lists, so each list must keep at least one entry.
  - Root `layouts/404.html` takes precedence over the theme's `404.en.html` and renders per edition (`/pt-br/404.html`).

## Research Log

### Current repository state
- **Context**: Brownfield; brief reports broken `hugo.toml`.
- **Sources Consulted**: working tree, `git show HEAD:hugo.toml`, `config/_default/*`, `themes/hugoplate/layouts/**`, `_vendor/github.com/gethugothemes/hugo-modules/**`, `scripts/*.js`, `package.json`, CI files.
- **Findings**:
  - Working-tree `hugo.toml` only has top-level `[en]`, `[en-gb]` … tables (ignored by Hugo). `HEAD:hugo.toml` holds the full stock config: `baseURL="/"`, `theme="hugoplate"`, `defaultContentLanguageInSubdir=false`, `[services.googleAnalytics]`, `[permalinks.page]`, `[pagination]`, `[build.buildStats]` + cachebuster, module mounts (`assets`, `hugo_stats.json → assets/notwatching/hugo_stats.json`), `[outputs]` (HTML, RSS, WebAppManifest, SearchIndex, llms, llmsfull, md), imaging, caches, markup, media types, output formats and `[[params.plugins.css|js]]` lists.
  - `scripts/themeGenerator.js` (run by `pnpm dev`/`build`) reads `^theme = "…"` from root `hugo.toml` and writes `themes/hugoplate/assets/css/generated-theme.css` from `data/theme.json` (`colors.default|darkmode.theme_color|text_color` → `--color-*`, fonts, type scale). The broken `hugo.toml` therefore also breaks the build script. Any extra key added under `theme_color` becomes a `--color-<key>` token without generator changes.
  - `scripts/themeUpdate.js` (`pnpm update-theme`) deletes and re-downloads `themes/hugoplate/{assets,layouts}`; root overrides survive, `generated-theme.css` is regenerated by the next build.
  - Theme `baseof.html` hard-codes `itemtype="http://schema.org/WebPage"`, calls `preloader`, `gtm-noscript`, `announcement`, `search-modal`, and caches `essentials/style.html` / `essentials/script.html` with `partialCached` (no variant → page-independent). Theme `essentials/head.html` calls `basic-seo`, GA, GTM, custom-script and search-index.
  - Theme `assets/js/main.js` only initialises a Swiper testimonial slider; removing the Swiper plugin without overriding `main.js` would throw a ReferenceError.
  - Theme `components/theme-switcher.html` contains the light/dark/system logic (localStorage) and is reusable as-is.
  - `params.toml` references `images/logos/cardapiofc_logo_light.svg`, but only `cardapiofc_logo_dark.svg` exists in `assets/images/logos/`.
  - CI/dev configs: `netlify.toml` (HUGO 0.165.0, GO 1.25.1, pnpm), `.gitlab-ci.yml` (GO 1.23.3, Node 18, npm), `amplify.yml` (GO 1.23.3, npm), `vercel.json` + `vercel-build.sh`, `.devcontainer/Dockerfile` (HUGO 0.165.0, GO 1.24.0, node:23). `package-lock.json` exists on disk (gitignored) next to `pnpm-lock.yaml`; `package.json` has no `packageManager` field.
  - Demo content lives in `content/english/` (blog, authors, about, contact, pages/elements, pages/privacy-policy, sections/testimonial, sections/call-to-action); `.sitepins/` holds the demo CMS config; demo images in `assets/images/` (avatar*, banner, call-to-action, service-*, gallery/, no-search-found, image-placeholder).
- **Implications**: restore from HEAD then prune; reuse the theme's cached style/script partials but keep one lazy plugin entry each; override `main.js`; own `baseof.html` to provide per-page hook slots.

### Hugo multilingual behaviour (probed on local Hugo 0.169.0 extended; must be re-verified on the pinned 0.165.0 during implementation)
- **Context**: Registry, i18n fallback, time zone access, 404, default-language alias.
- **Sources Consulted**: https://gohugo.io/configuration/languages/, https://gohugo.io/functions/time/format/, https://gohugo.io/functions/time/in/, https://gohugo.io/configuration/module/#mounts, https://gohugo.io/functions/css/tailwindcss/, executable probe site in `scratch/i18nprobe` (outside the repo).
- **Findings**:
  - Language keys `label`, `locale`, `direction`, `contentDir`, `weight`, `title`, `timeZone`, `params` work; `site.Language.Locale` returns `pt-PT`; `hugo.Sites` iterates all editions (`.Site.Sites` is deprecated since 0.156.0).
  - i18n probe: `i18n/{en,pt,pt-pt}.yaml` → `pt-pt` shows `Equipa` but English for keys missing in `pt-pt.yaml`; `pt-br` shows English. With mounts `[i18n/pt.yaml→i18n/pt-pt.yaml, i18n/pt.yaml→i18n/pt-br.yaml, i18n→i18n]` (directory last) → `pt-pt`: `Equipa` + `Jogos`; `pt-br`: `Time` + `Jogos`. With the directory mount first, the base file shadowed the regional file (no merge in that order).
  - Adding custom mounts for a target root disables that root's default mount; the `i18n → i18n` mount must be declared explicitly.
  - `site.Language.TimeZone` / `.Location` do not exist. `time.AsTime` of an offset-less string uses the edition `timeZone` (`-0300 -03` for pt-br), so `(time.AsTime "2000-01-01T00:00:00").Location.String` returns the configured zone name.
  - `time.Format ":date_medium"`: en `Nov 8, 2026`; pt-PT `08/11/2026`; pt-BR `8 de nov. de 2026`. `":time_short"`: en `7:45 pm`, pt `19:45`. Layout strings are localised (`Monday 2 January` → `domingo 8 novembro`).
  - Root `layouts/404.html` beats theme `404.en.html`; output `/404.html`, `/pt-pt/404.html`, `/pt-br/404.html` with per-edition strings.
  - Default config produced `public/en/index.html` (alias to `/`); `disableDefaultLanguageRedirect = true` removed it.
  - `css.TailwindCSS` with `inlineImports` resolves `@import` through the union file system and respects project overrides of theme files, so root `assets/css/custom.css` (imported by theme `main.css`) can import further root files.
- **Implications**: registry in `languages.toml` + edition params; i18n mounts in `hugo.toml`; zone label + offset from registry; i18n-driven date layouts; build-time validation partial.

## Design Decisions

### Decision: Edition registry in Hugo language config
- **Context**: 2.1–2.8; brief asks for Hugo-native storage.
- **Alternatives Considered**: 1) `data/editions.json` read by templates; 2) `languages.<code>` + `params.edition`.
- **Selected Approach**: `config/_default/languages.toml` holds each edition (`label`, `locale`, `direction`, `contentDir`, `weight`, `title`, `timeZone`, `params.description`, `params.copyright`, `params.edition.{country,hreflang,i18nBase,timeZone,zoneLabel,isGlobal}`); code and prefix are derived from Hugo (`.Language.Lang`, `.Home.RelPermalink`). Templates read edition data only through `edition/current.html` / `edition/all.html`.
- **Rationale**: Hugo routes, locales and translations natively; no duplicate language list.
- **Trade-offs**: `timeZone` is duplicated (language level for parsing, params for display) → guarded by `edition/validate.html`.
- **Follow-up**: verify `label`/`locale` keys on 0.165.0.

### Decision: i18n base + regional overrides via single-file mounts
- **Context**: 4.1–4.3, 2.6–2.7.
- **Alternatives Considered**: 1) full copies per edition + parity check; 2) wrapper partial with manual fallback (impossible: `T` cannot target another language); 3) single-file mounts.
- **Selected Approach**: base files `i18n/en.yaml`, `pt.yaml`, `es.yaml`; regional files `en-gb.yaml`, `en-ie.yaml`, `pt-pt.yaml`, `es-ar.yaml` with differing keys only; `hugo.toml` mounts each base file onto every edition target that uses it, then mounts `i18n` last. Each base file defines `i18n_base`, validated against `params.edition.i18nBase`.
- **Rationale**: config-only, verified by probe, adding an edition of an existing language = registry entry + one mount line.
- **Trade-offs**: mount order is load-bearing → documented and validated.

### Decision: Own `baseof.html` with a hook dispatcher
- **Context**: 10.1–10.6, seo-social/analytics-consent head conflict.
- **Selected Approach**: `site/hook.html` renders `_partials/hooks/<name>.html` if it exists, else an optional fallback; names are whitelisted. Foundation creates no file under `hooks/`; each downstream spec creates only its own hook files.
- **Rationale**: no shared file ownership; empty slots cost nothing.

### Decision: Display zone = registry label + computed offset
- **Context**: 5.2, 5.5, 5.6; live-site "local" mislabel; unreliable Go abbreviations.
- **Selected Approach**: `time/zone.html` returns `{label, offset, iana}` where `offset` is derived from `Format "-07:00"` of the converted time (`UTC+1`, `UTC−3`, `UTC+5:30`); Global shows only `UTC`.

### Decision: Time layouts in i18n files
- **Context**: 5.3; locale styles (`:time_short` → `7:45 pm` in en) are not ideal for kick-offs.
- **Selected Approach**: layouts `layout_time` (`15:04`), `layout_date_short`, `layout_day_heading`, `layout_datetime` per base language with regional overrides; formatted with `time.Format`.

### Decision: Global menus with identifier-based labels
- **Context**: 6.5–6.7, 2.6.
- **Selected Approach**: `config/_default/menus.toml` (site-wide, applies to every edition) with `identifier`s; labels from `T (printf "menu_%s" .Identifier)`; URLs via `relLangURL`. Downstream pages join menus with front matter `menus:`.
- **Rationale**: a new edition needs no menu file.

### Decision: Disable unused modules and outputs
- **Context**: 3.4–3.6, 11.x.
- **Selected Approach**: remove module imports with no remaining consumer (accordion, tab, modal, gallery-slider, videos, social-share, open-remark, preloader, announcement, mermaid, notice, button, table-of-contents, font-awesome, search); keep images, pwa, llms-txt, basic-seo, site-verifications, google-tag-manager, adsense, cookie-consent, custom-script, render-link, gzip-caching (downstream-owned decisions). Outputs: home `HTML, WebAppManifest, llms, llmsfull`; page/section `HTML`; `disableKinds = ["taxonomy","term","rss"]`; remove the SearchIndex format.
- **Trade-offs**: app-deeplinks must re-add a search module/format if it chooses the stock search.

### Decision: Site Build check as a dependency-free Node script
- **Context**: 1.x, 3.x, 4.4, 5.7, 7.4, 11.x, 12.4 need automated verification; no test framework exists.
- **Selected Approach**: `scripts/check-site.mjs` (Node built-ins only: `fs`, `path`, `zlib`) run via `pnpm check` after `pnpm build`, and `pnpm check:components` against a development build of the styleguide pages into `resources/_check/`. Build-time invariants (registry, time values) fail inside Hugo via `errorf`.

## Synthesis Outcomes
- **Generalisations**: one hook dispatcher for all slots (head/body/footer/home-main); one time pipeline (`parse → local → format/zone`) reused by kick-off, date group and 404-free shells; one Edition view-model for every consumer.
- **Build vs adopt**: adopt theme `style.html`, `script.html`, `theme-switcher`, images module `logo`/`favicon`/`image`, `themeGenerator`; build `baseof`, `site/*`, `edition/*`, `time/*`, `cfc/*` components, `check-site.mjs` (no suitable existing module).
- **Simplifications**: no per-edition menu files; no per-edition content beyond `_index.md`; switcher uses native `<details>` (no JS required); crest fallback uses an initials underlay with a one-line `onerror` hide instead of a JS library; no styleguide in production.

## Risks & Mitigations
- Probes ran on Hugo 0.169.0, pin is 0.165.0 — first implementation task re-runs the i18n/time/404 checks under the pinned version (pre-flight per AGENTS.md).
- Mount order regression silently restores English fallback — `edition/validate.html` compares `T "i18n_base"` with the registry and fails the build.
- Theme update changes `style.html`/`script.html` contracts — `pnpm check` after `pnpm update-theme`; revalidation trigger documented.
- Missing light logo asset — fall back to `logo_text` until the user supplies `cardapiofc_logo_light.svg`; flagged as open question.
- Inline `onerror` on crests conflicts with a future strict CSP (edge-delivery headers) — documented revalidation trigger; alternative is a 1-line delegated listener in `main.js`.
- Downstream edits to shared config arrays (`[outputs]`, `[security.http]`, module imports) — declared append-only seams; foundation-owned entries must not be removed.
